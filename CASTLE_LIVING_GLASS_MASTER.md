# CASTLE LIVING GLASS ENGINE

## Master Design & Engineering Brief

### Diseñados a su Imagen — Grupo Castillo / Castle Platinum

---

## 0. STATUS

**Project:** Diseñados a su Imagen
**Program:** Castle Platinum
**Internal Visual System:** Castle Living Glass Engine
**Status:** Active — Experimental / Production Development
**Primary Objective:** Transform the existing church website into a unique, contemporary, highly artistic digital experience built around living Liquid Glass.

This document is the primary source of truth for the Castle Living Glass direction.

Before changing code, architecture, styles, animations, assets, or visual systems, read and follow this document.

---

# 1. PROJECT CONTEXT

Diseñados a su Imagen is a real church website and also the first experimental implementation of the visual and technological system that will later become part of Grupo Castillo's premium offering.

The objective is NOT to create another modern church website.

The objective is NOT to create a standard corporate website with security features.

The objective is NOT to imitate generic glassmorphism, common Framer templates, Awwwards templates, Apple-style cards, or existing Liquid Glass demos.

The objective is to create a visually distinctive digital experience that feels like a living work of digital art while remaining highly usable, accessible, performant, responsive, and appropriate for a church.

The website must feel:

* Contemporary.
* Artistic.
* Cinematic.
* Organic.
* Spiritual.
* Elegant.
* Experimental.
* Premium.
* Human.
* Interactive.
* Memorable.

The visual experience should create the reaction:

> "This does not look like a normal church website."

while still communicating:

> "This is a church."

# 2. CORE CREATIVE DIRECTION

The central concept is:

## DIGITAL LIVING ART + LIQUID GLASS

The website should feel as though the interface itself is made from a living material.

Liquid Glass is not merely a blur effect.

The interface should combine:

* Atmospheric effects.

# 4. CASTLE LIVING GLASS PRINCIPLE

The primary rule is:

> EVERYTHING BELONGS TO THE SAME MATERIAL WORLD.

The website should not look like:

background + animation + glass cards + normal UI.

Instead:

matter + light + glass + typography + interaction + content

should feel like one unified system.

The visual engine should make it possible for the user to perceive that:

* the background has physical depth;
* glass interacts with the environment;
* light exists inside and around the glass;
* surfaces deform;
* content can appear embedded within the material;
* transitions can transform one visual state into another;
* interaction influences the scene;
* different pages belong to the same visual universe.

# 5. VISUAL LANGUAGE

## 5.1 Base Environment

The base environment should generally use:

* Deep OLED black.
* Near-black gradients.
* Controlled atmospheric illumination.
* Large areas of negative space.
* Subtle environmental texture.
* Carefully controlled highlights.

Avoid generic dark gradients that make the site look like a SaaS dashboard.

---

## 5.2 Glass

Glass should communicate materiality.

Desired properties may include:

* Refraction.
* Distortion.
* Blur.
* Edge highlights.
* Fresnel-like response.
* Internal illumination.
* Depth.
* Thickness.
* Subtle chromatic aberration.
* Light interaction.
* Glass-on-glass relationships.

However, effects must remain visually controlled.

Avoid excessive:

* Blur.
* Saturation.
* Chromatic aberration.
* Glow.
* Borders.
* Transparency.
* Reflection.

The goal is premium optical material, not visual noise.

---

# 6. CASTLE MATERIAL SYSTEM

The engine should support multiple material families.

### Glass Clear

Used for navigation and lightweight interface surfaces.

### Glass Frosted

Used for content requiring strong readability.

### Glass Dark

Used against bright visual scenes.

### Glass Refractive

Used for highly visual hero elements and major interactive surfaces.

### Glass Interactive

Used for buttons, controls, hover states, pointer interactions, and touch responses.

### Glass Cinematic

Used for major visual compositions and hero scenes.

### Glass Organic

Used for irregular, sculptural, procedural, or fluid forms.

These are conceptual material classes.

Do not implement all materials blindly.

Create only what is visually justified.

# 7. LIVING MOTION SYSTEM

Motion is a first-class part of the project.

Animations must not feel like standard UI animation.

Avoid relying primarily on:

* fade-in;
* fade-up;
* generic slide-in;
* repetitive parallax;
* preset easing;
* template-style reveal animations.

Motion should instead communicate:

* mass;
* inertia;
* fluidity;
* pressure;
* elasticity;
* floating;
* deformation;
* transformation;
* environmental reaction.

Objects should appear to have physical properties.

Motion should be:

* continuous where appropriate;
* subtle;
* deliberate;
* organic;
* responsive;
* cinematic.

Nothing should move simply because it can.

# 15. WEBGL / GPU RULES

GPU effects may be used heavily for hero experiences, but implementation must remain controlled.

Do not create unnecessary independent WebGL contexts.

Prefer shared rendering architecture when practical.

Avoid dozens of independent high-cost canvases.

Use:

* shared scenes;
* controlled render loops;
* lazy initialization;
* visibility detection;
* resolution scaling where necessary;
* adaptive quality;
* device capability detection.

The visual quality should scale according to the device.

---

# 16. MOBILE

Mobile is NOT desktop compressed.

The visual system must have a mobile composition strategy.

On mobile:

* reduce unnecessary visual complexity;
* preserve the artistic identity;
* adapt composition;
* change scale and motion;
* avoid excessive GPU load;
* preserve readability;
* preserve touch interaction;
* avoid hover-dependent functionality.

The mobile hero should feel deliberately designed.

---

# 17. PERFORMANCE

The website must remain production-quality.

Maintain strong:

* LCP.
* CLS.
* INP.
* accessibility.
* semantic structure.
* SEO.
* loading behavior.

Do not sacrifice the user experience for visual effects.

Use adaptive rendering when appropriate.

Possible strategies include:

* reduced particle count;
* lower render resolution;
* fewer layers;
* simplified shaders;
* disabled expensive effects on weak devices;
* static or CSS fallback;
* reduced motion;
* deferred initialization.

The goal is not maximum technical complexity.

The goal is maximum perceived quality per unit of computational cost.

---

# 18. ACCESSIBILITY

Maintain WCAG-oriented behavior.

Never allow visual effects to make content inaccessible.

Requirements include:

* keyboard accessibility;
* visible focus;
* sufficient contrast;
* semantic HTML;
* accessible labels;
* form accessibility;
* `prefers-reduced-motion`;
* non-WebGL fallback;
* content availability without the visual engine.

If WebGL fails, the site must still function.

---

# 19. SEO

Do not destroy the existing SEO implementation.

Preserve:

* titles;
* descriptions;
* semantic structure;
* structured content;
* indexing behavior;
* canonical URLs where applicable;
* Open Graph;
* relevant metadata.

The visual engine must sit beneath the content architecture rather than replacing it.

# 24. CASTLE PLATINUM RELATIONSHIP

Castle Platinum is not the visual engine itself.

Castle Platinum is the premium service environment in which a system like Castle Living Glass Engine can exist.

The visual experience is what the client sees.

The engineering, reliability, quality, performance, maintenance, and security are what make that experience production-ready.

The visible hierarchy should therefore be:

```text
CLIENT EXPERIENCE
        ↓
CASTLE LIVING GLASS
        ↓
CASTLE PLATINUM
        ↓
ENGINEERING / QUALITY / RELIABILITY
```

Do not make the website feel like a security product.

The technology should remain largely invisible to the visitor.

---
